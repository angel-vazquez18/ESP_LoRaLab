# Development and verification

All commands below start at the repository root. Python source, package metadata
and uv.lock live in `testbed/`. npm metadata/lock live in `testbed/frontend/`.
Activate ESP-IDF v6.0.2 separately for firmware; host work does not require it.

| Task | Root command |
| --- | --- |
| Install host dependencies | `make setup` |
| Serve dashboard/backend | `make serve` |
| Frontend development server | `make frontend-dev` |
| Host regression suite | `make test` |
| Python lint | `make lint` |
| Production dashboard build | `make frontend` |
| Frontend formatting check | `npm --prefix testbed/frontend run format:check` |
| Update generated contracts | `make contracts` |
| Detect generated-contract drift | `make contracts-check` |
| Repository paths / hardware planning invariants | `make repo-check` |
| Full host and repository checks | `make check` |
| Main node scaffold build | `make firmware-build` |
| Diagnostic firmware build | `make diagnostic-build` |

Expanded core checks:

```sh
uv run --project testbed pytest testbed/tests
uv run --project testbed ruff check testbed/src testbed/tests scripts
npm --prefix testbed/frontend run build
uv run --project testbed python scripts/generate_contract.py --check
python3 scripts/check_repository.py
```

Focused checks may use the same pytest command with an explicit file or `-k`
selector. Run the full suite when changing shared interfaces, lifecycle/evidence,
layout or procedure source-profile hashing. GUI interaction changes need browser
checks where available; identify unavailable browser verification explicitly.

Firmware builds do not run from the host virtual environment:

```sh
source /Users/anken18/.espressif/v6.0.2/esp-idf/export.sh
idf.py -C firmware/lora_node build
idf.py -C firmware/diagnostic build
```

No make target flashes a board or opens a physical port. The diagnostic target's
README retains its separate operator procedures. Physical operations require
matching device/revision, released host ownership and explicit task authorization.

## Generated content

Schemas in root contracts/v2 and `firmware/diagnostic/main/contract_schema.h`
are generated from host models. `--check` computes expected bytes without writing
files and fails on drift. Default profiles and public vectors are maintained source,
not generated by that command. The board JSON and wiring diagram are planning
records, currently maintained together by hand; firmware bindings are future work.

## Clean checkouts

Environments, node_modules, generated ESP-IDF sdkconfig/build/managed_components,
runtime stores and local evidence are ignored. Keep dependency locks and sdkconfig
defaults in source control. The original tracked scaffold build was relocated to
ignored local migration storage, so its old tracked paths appear deleted until
this restructuring is committed. No history rewriting or automatic commit occurs.
